# "公开可见的其他参与者动作"变量：免费数据可行性核对

> 日期：2026-11-15。作者：researcher。性质：**文档与接口层面的可行性核对，不是实验**；没有建模，没有回测。
> 数据源约束：AKShare 为主（免 token），BaoStock 作交叉核对；不用 Tushare。
> 样本期（以 `experiments/PLAN.md` §2.2 为准）：2010-01-01 至 2026-06-30，冻结留出集 2022-01 至 2026-06。

## 0. 先说结论

- **免费数据 + 时点安全条件下最可行的三类：** (d) 融资融券个股明细、(c) 龙虎榜（按日全市场汇总与机构买卖统计）、(e) 大宗交易。三者都能"按日期查全市场"，实测都取到了 2012 年 1 月的数据，并且都是交易所在当日收盘后或次日开盘前公布的数据，时点规则清楚。
- **有条件可用：** (b) 中的**实际**增减持（`stock_ggcg_em` 有公告日，1994 年起）；(a) 解禁日程（日程本身事先已知，但东财表没有公告日字段，且完整性存疑）；(f) 股东户数（有公告日，但实测只到 2013 年，退市股查询失败）；(h) 回购 / 质押 / 机构调研（各有明显限制）。
- **不可用或须放弃：** (b) 中的增减持**预披露（计划）**——没有找到结构化接口；(g) 北向个股持股——只有 2017-03-16 至 2024-08-16，交易所自 2024-08-19 起不再每日披露，**断点落在留出集中间**，不是换数据源能解决的。
- **BaoStock 对 (a)–(h) 都没有找到对应数据**（未在官网核实，见 §2.9），所以这些变量**没有第二个免费来源可交叉核对**，除 (a) 解禁有东财 / 新浪两个上游、(b) 有东财 / 交易所 / 同花顺三个上游之外。
- Python 3.14 下 `akshare` 1.20.63 **安装成功**；做了 40 次小调用，**32 次成功，8 次失败**（详见 §3）。

实测的局限，读下面所有判断时都要记住：
1. 每个接口只做了 1–2 次调用（单只股票或单个日期）。"取到 2012 年某三天"不等于"2010–2026 每天都有、都完整"。
2. 没有与任何第二来源核对数值，**数据正确性完全没有检验**。
3. 失败只尝试了一次（仅深交所两融重试过一次），无法区分"上游没有这段数据"和"当时网络 / 限流问题"。
4. 东财系接口返回的是上游数据库的**当前状态**，不是历史上某天能看到的版本。

## 2. 逐类核对

所有东财接口共用同一个上游地址 `https://datacenter-web.eastmoney.com/api/data/v1/get`，以不同的 `reportName` 区分【源码】。这意味着：结构统一、容易自己写分页；但也是单点，上游一改，这些接口同时失效。

返回字段【实测】：
- 东财 detail：序号、股票代码、股票简称、解禁时间、限售股类型、解禁数量、实际解禁数量、实际解禁市值、占解禁前流通市值比例、解禁前一交易日收盘价、解禁前20日涨跌幅、解禁后20日涨跌幅。
- 新浪 queue：代码、名称、解禁日期、解禁数量、解禁股流通市值、上市批次、公告日期。

可回测性判断：
- **公告日 / 披露日：** 东财接口**没有**；新浪接口**有**"公告日期"。实测 600000 的公告日期比解禁日期早数日到数年（如解禁 2015-10-14、公告 2010-10-16），与"解禁日程在发行时就已确定"一致。
- **历史深度：** 东财按日期查取到了 2012-01；600000 在东财最早一批是 2010-09-29，而新浪还有 2007–2008 年的批次——东财的覆盖起点**可能在 2010 年前后，未验证**。样本期起点 2010-01 处于边缘。
- **是否当前快照：** 不是只有未来日程，历史批次都在。但表内有事后字段（"解禁后20日涨跌幅"、"实际解禁数量"、"实际解禁市值"），**必须丢弃或滞后**；"股票简称"是当前名称（2012 年的记录显示的是今天的简称）。
- **退市股：** 300104（乐视网，2020 年退市）能查到，但只有 1 行（2016 年股权激励）。它 2010 年上市，按常理应有首发限售股的解禁批次，这里没有——**东财表不完整，或对退市股不完整，未验证**。这是本类最大的疑点。
- **失效风险：** 本次 5 次调用全部成功。GitHub issue 列表第一页（按关键词检索，25 / 83 条）标题中没有 restricted_release 相关条目；更早或正文中是否有，未验证。
- **判断：有条件。** 条件：(i) 只用"解禁日、限售股类型、计划解禁数量"这类事先确定的字段；(ii) 用新浪的公告日期做时点核对（解禁日 − 公告日 > 0 的比例）；(iii) 先查清东财表的完整性。

- **披露日：** 没有单独字段。【规则】龙虎榜由交易所在上榜当日收盘后公布，所以"上榜日 = 披露日"，t 日数据可用于 t+1 日决策；本次未核实规则原文，也未核实历史上是否一直如此。
- **历史深度：** 按日期查取到 2012-01；按股票查最早到 2010-08。2010-01 至 2010-08 是否有，未实测。
- **是否当前快照：** 主表不是。但**有三类事后字段必须丢弃**："上榜后 N 日"涨跌幅；"解读"里的"成功率 xx%"（看起来是席位的历史统计，统计截止到哪天文档未说明，按前视处理）；"名称"是当前简称。
- **退市股：** 在（300104 有 144 个上榜日；2012 年机构统计里有后来退市的股票）。
- **抓取量：** 汇总表和机构统计表按日期查，量小。**席位明细要按（股票、日期、买 / 卖）逐一调用**，按实测每天 60–70 只上榜粗估，全样本是数十万次调用——对爬虫接口不现实，除非只做子样本。
- **内生选择：** 股票是因为当日价格 / 换手异常才上榜的，变量只在极端日存在；上榜标准历史上改过【规则，未核实】。这是研究设计问题，不是数据问题，但决定了它只能作为事件型变量。
- **失效风险：** 5 次调用全部成功；issue 第一页标题中没有 lhb 相关条目，更多未验证。
- **判断：能**（按日汇总 + 机构买卖统计）；席位明细**有条件**（抓取量）。

返回字段【实测】：
- 上交所：信用交易日期、标的证券代码、标的证券简称、融资余额、融资买入额、融资偿还额、融券余量、融券卖出量、融券偿还量。
- 深交所：证券代码、证券简称、融资买入额、融资余额、融券卖出量、融券余量、融券余额、融资融券余额（**没有日期列，没有融资偿还额**；两所字段不对称）。

可回测性判断：
- **披露日：** 没有单独字段。【规则】交易所在 T+1 日开盘前公布 T 日两融数据。PLAN 的约定是 t 日决策只用 t−1 日及以前的数据，若规则属实则刚好够用；**保守做法是多滞后一天**。规则原文与历史上的公布时间未核实。
- **历史深度：** 两所都取到 2012-01-04。2010-03 两融启动至 2011 年未实测。
- **是否当前快照：** 不是。这是交易所按日存档的数据，按日期查得到的就是当日名单，**天然是时点数据**，表内没有事后字段；简称是当日简称（2012 年的 000001 显示为"深发展Ａ"）。
- **退市股：** 按日期查全市场，当日是标的就在表里，不依赖今天是否上市。未专门找一只已退市的标的核对。
- **覆盖面限制（重要）：** 只有两融标的才有数据。实测 2012-01-04 两所合计 284 行（含 ETF），2024-01-02 合计约 3,600 行。**2012–2014 年前后标的很少**，变量在样本前段对多数股票是缺失的；"是否为两融标的"本身与规模、流动性高度相关，必须作为控制变量。
- **抓取量：** 每个交易日每所一次，全样本约 8,000 次调用，可行。
- **失效风险：** 深交所域名本次 5 次调用中 2 次连接失败（一次超时、一次被重置，后者重试成功）；issue #6591"AKShare 接口问题报告 stock_margin_szse"（2025-10-07，已关闭）。批量抓取必须带重试和断点续抓。
- **判断：能。** 这是八类里时点性质最干净的一类。

## 4. 结论表

"能"的含义是"接口层面看不到阻碍，值得进入数据审计"，**不是"数据已验证可用"**。

## 5. 建议

**建议纳入数据审计、作为 Z 候选的（免费 + 时点可论证）：**
1. **(d) 融资融券个股明细。** 交易所官方按日存档，按日期查，表内无事后字段。代价是变量只对两融标的存在；建议同时把"是否两融标的"作为控制变量，并考虑主分析限定在 2014 年或 2015 年以后（待审计给出各年覆盖率后再定）。
2. **(c) 龙虎榜的按日汇总与机构买卖统计** 以及 **(e) 大宗交易**。都是按日期查全市场、当日收盘后披露的事件型数据，取到了 2012 年。两者都很稀疏，适合做"过去 N 日内是否出现 / 净买入方向 / 折价率"这类事件特征，不适合当连续状态变量。
3. **备选：(b) 实际增减持（`stock_ggcg_em`，以公告日为时点）与 (a) 解禁日程。** 前者有公告日、历史长，但表是回填的；后者日程事先确定，但东财表的完整性要先查清。两者经审计通过后可加入。

**建议放弃的：**
- **(g) 北向个股持股**：数据在 2024-08 之后不再每日公布，无解。
- **(c) 龙虎榜席位明细的全样本抓取**：调用量不现实。
- **(h) 回购的实施进度字段**：快照，前视。

**免费数据做不了、需要用户通过学校渠道（CSMAR / Wind / RESSET 等，具体哪个库有哪张表我没有核实）才能做的：**
- **增减持预披露（计划公告）**的结构化数据。这恰恰是"对手事先告诉你他要卖"最直接的变量，免费来源只有公告标题。
- **2013 年以前的股东户数**，以及退市股的股东户数（若审计确认东财已删除）。
- **完整的解禁明细**（若审计确认东财 / 新浪都不完整）。
- **带真实公告时间戳、未经回填修订的**增减持与回购逐次公告记录。

**需要用户决定的事：**
1. 是否接受"对手动作"变量只在部分股票（两融标的）和部分日期（事件日）上有值——这会让 Z 的析因检验变成子样本分析。
2. 是否愿意为增减持预披露等走学校数据库；不愿意的话，这一变量从研究中去掉。
3. 是否把 (g) 北向彻底去掉（我的建议），还是保留为 2017-03 至 2024-08 的事先声明的稳健性子样本。
4. 抓取预算：(d) 约 8,000 次请求、(c)(e) 按月或按周分段各几百次，可接受；是否允许为 (a)(f) 逐只股票抓取（每类约 5,000 次以上）。

## 6. 新增数据审计项（供日后并入 `PLAN.md` §2.4；本文件不改 PLAN）

阈值均为**占位值**，与 PLAN 现有审计项一样需在看到任何结果之前由组长 / 用户确定。编号用 OA（opponent action）以免与现有 A1–A13 冲突。

| # | 审计项 | 怎么查 | 通过标准（占位） | 不通过时 |
|---|---|---|---|---|
| OA1 | 披露时点可得 | 每个拟用变量：有公告日字段的，统计公告日 ≥ 事件日的比例及二者间隔分布；没有公告日字段的（两融、龙虎榜、大宗），找到并存档交易所的公布时间规则原文，确定固定滞后 | 有公告日的：公告日缺失率 ≤ 1%，公告日早于事件日的异常记录 ≤ 0.5% 且逐条解释；无公告日的：规则原文已存档，特征一律按"披露日 + 1 个交易日"起可用 | 该变量不进入主分析 |
| OA2 | 事后字段清除 | 列出每张表的全部字段，逐个标注"披露时已知 / 事后计算 / 当前快照"；代码里用白名单取字段 | 进入特征的字段 100% 标注为"披露时已知"；"上榜后 N 日""解禁后 20 日涨跌幅""实施进度""最新价""解读"等不在白名单 | 修到通过为止，否则不用该表 |
| OA3 | 历史深度与逐年覆盖 | 每个变量按年统计：有记录的交易日占比、有记录的股票数占当年股票池的比例 | 主分析期内每年"有记录交易日占比" ≥ 95%（事件型变量改为：无连续 20 个交易日全市场零记录）；覆盖起点晚于 2010-01 的，把该变量的分析期起点写死为实测起点 | 缩短该变量的分析期并在论文中声明；起点晚于 2018-01 的不进入主分析 |
| OA4 | 退市股是否保留 | 取 PLAN A1 得到的退市股名单中随机 30 只，逐一查询每个变量在其上市期间是否有记录，并与同期、同规模的存续股比较记录数 | 退市股"有记录比例"不低于匹配存续股的 90% | 该变量标记为"有幸存者偏差"，只作探索性分析，不用于主结论 |
| OA5 | 完整性抽查（与第二来源） | 有两个上游的（解禁：东财与新浪；增减持：东财、上交所、同花顺），随机抽 50 只股票比对记录；只有一个上游的，随机抽 30 条记录与交易所 / 巨潮的公告原文人工核对 | 两源记录匹配率 ≥ 95%；人工核对的日期和数量一致率 ≥ 95% | 标记为"未经核对"，不用于主结论；差异清单写入审计报告 |
| OA6 | 修订 / 回填检测 | 审计开工时把每张表完整抓一份并记录日期；至少 30 天后重抓同一历史区间，比较两份 | 历史区间（抓取日 60 天以前的记录）的变动行占比 ≤ 0.5% | 报告变动率；以第一份快照为准并冻结，论文中说明 |
| OA7 | 覆盖的内生性 | 对"只对部分股票存在"的变量（两融标的、龙虎榜、沪深股通），按日统计有值与无值股票在市值、流动性、波动率上的差异 | 不设通过线；必须报告，并把"是否有值"的指示变量加入基础特征集 B，使 Z 的增量检验不把"是否为标的"误当成信息 | — |
