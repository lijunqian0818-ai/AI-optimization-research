## 2. 实现了什么

### 2.1 时点约定（第一要求）

- **截点就是决策日 t。** 每个特征函数都显式接收 `cutoff`（必须是交易日，缺省或非交易日直接报错）。函数只能用：日期严格早于 t 的日线行（即截至 t−1 收盘）；交易日历（开盘前已公开）；"可用日 ≤ t"的事件记录。对应 PLAN §3.1 的 G_t。
- 日线类特征先在"数据日 s"上计算（只用 ≤ s 的行），再把索引换成决策日 next(s)。**返回的特征表一律以决策日为索引，第 t 行只依赖 G_t。**
- 复权因子 F_t 用到当日 preclose（t 日开盘前信息），但决策日 t 的特征只用到 F_{t−1} 为止，没有用 t 日的任何数值。
- 事件类（Z_O）：交易日 s 的事件自决策日 t ≥ s + ℓ 起可用，ℓ 以交易日计，取自 `config.ZO_LAG`。当前三类都是 **ℓ = 2**：

| 类 | 用哪个日期定时 | ℓ | 依据 | 核对状态 |
|---|---|---|---|---|
| 龙虎榜 LHB | 上榜日（= 交易日） | 2 | PLAN §5.6.2 / RC-18：披露条件已核对，**条文没有规定公布钟点** | 条件已核对；时点无条文 |
| 大宗交易 BLK | 交易日期 | 2 | PLAN §5.6.2：只有当两所全样本期的"每个交易日结束后公布"条款都存档时才可取 1。`rule_verification.md` C2 只打开了深交所 2013、2026 版与上交所 2023、2026 版，**更早年份的条款未存档，条件不满足，取 2** | 部分核对 |
| 实际增减持 INS | **公告日**（`NOTICE_DATE`），不用变动起止日 | 2 | PLAN §5.6.1、§5.6.2：表里只有日期 | 公告日本身**无法从免费数据核对**（OA10 未做） |

  ℓ 是参数，另一取值可作敏感性分析直接调用（`zo_lags=`）。
- INS 的公告日落在非交易日时（试跑的 4 个公告年文件里 18.9% 的行如此，多为周六）：**向后**滚到下一个交易日再加 ℓ。PLAN 没有规定，这是保守的读法（§5 第 9 条）。
- 回填行（INS）：按 PLAN 只用公告日定时。供应商的录入时间 `EITIME` 只在诊断里用来统计回填比例，**不进入任何特征**（有测试：把 `EITIME` 全部改掉，特征逐位不变）。回填行与非回填行在特征里不作区分——公告日字段是否可信只能靠 OA10 审计。

### 2.2 自建复权因子（PLAN §3.11）

`bars.own_adjust_factor`：F_t = Π_{s≤t} close_{s−1} / preclose_s，对该股全部行（含停牌行）连乘，首行 F = 1；复权价 = 不复权价 × F；复权成交量 = 成交量 / F。"s−1"指该股的上一行。

与供应商因子的差别：
1. **不读任何供应商因子表或复权价。** 只用日线里的 close 与 preclose。
2. 它是交易所参考价隐含的**全收益指数**（现金红利按税前、按参考价再投资；配股按认购处理），不是除权后的价格，也不是 §3.8 约定下持有人的财富。BaoStock / 新浪的因子同样含现金分红（审计 A5、A23），所以性质相近；差别在来源与锚点。
3. **锚在首行**：某日的值一经算出，之后发生任何事件都不会改变（供应商的前复权因子锚在末行，会改写自己的历史）。供应商后复权因子锚在上市日，我们的首行若不是上市日（2008 年前上市的股票），两者水平差一个常数；所有特征都是同一只股票内部的比值，常数约掉（只差浮点舍入）。
4. 继承 preclose 字段的全部错误（审计发现的 2 个未解释跳变、1 条坏行会进入这些股票的特征）；**URS 日期的标记尚未实现**（清单还不存在）。
5. 某个交易日缺行时（审计与抓取都发现两只代码变更股各缺 2012-09-10）：因子用"上一条存在的行"续乘；缺的那天在标准化日线里补成 NaN 行、`present = False`，**不向前填充**，于是所有覆盖到它的窗口都是 NaN（250 日窗口约一年）。
6. 与 BaoStock 后复权因子的逐事件比较见 §3.4（只是描述，特征不依赖它）。

### 3.2 前视检测（`lookahead_synthetic.csv`、`lookahead_real.csv`）

做法（`lookahead.py`）：对决策日 t，先用完整数据、把截点设在很远的将来算出第 t 行作为基准；然后把 G_t 之外的东西毁掉再算，要求第 t 行逐位相同（NaN 位置一致，非 NaN 值按 64 位比特比较）。

| 检查 | 毁掉什么 |
|---|---|
| truncate | 数据不动，截点设为 t（只检验截点参数被一致地遵守；**它查不出"无视截点"的函数**，下面几项才查得出） |
| nan | G_t 之外的值全部置空 |
| shuffle | G_t 之外的值在 G_t 之外的行之间打乱（事件表连股票代码一起打乱） |
| noise | G_t 之外的数值乘以随机数并加噪声 |
| drop | 删掉 G_t 之外的行 |
| inject | 在 G_t 之外给被测股票添加伪造的事件记录 |

"G_t 之外"：日线与指数是日期 ≥ t 的行；事件表有两种口径——calendar（事件日 ≥ t）与 availability（事件日 + ℓ > t，即还包括日期早于 t、但按滞后规则尚不可用的记录）。availability 毁掉的是 calendar 的超集。

| 数据 | 股票 × 决策日 | 检查项 | 逐位相同 | 每行参与比较的非缺失列数 |
|---|---|---|---|---|
| 合成（5 只，含缺行、长停牌、除权、换手 > 1；每只 4 个随机日 + "事件刚可用的那天"与前一天） | 30 | 330（每个 11 项：truncate + 5 种 × 2 种口径） | **330** | 203–385（共 386 列） |
| 试跑真实数据（20 只；每只 2 个随机日 + 1 个"某事件刚可用"的日子，2010-01-26 至 2026-07-01） | 60 | 360（每个 6 项：truncate + 5 种 × availability 口径） | **360** | 160–384，中位数 358（共 386 列） |

真实数据只跑了 availability 口径（它包含 calendar 口径毁掉的全部内容），为了省时间；前视检测用的事件表只保留 20 只试跑股票的记录（特征代码本来就按代码过滤，基准行不受影响）。

反例（证明检测不是摆设）：
- 故意在特征里加入 t 日收盘价：nan / shuffle / noise / drop / inject 各项全部报不一致，truncate 项没有报（原因见上表）。
- 故意把事件滞后设为 1：availability 口径报不一致，calendar 口径与 truncate 不报——说明"日期早于 t 但尚不可用"的记录确实只有 availability 口径能查。

**检测查出并已修复的一处不一致。** 第一次运行时 `b0_BETA*`、`b0_RSQR*` 在 truncate 与 drop 两项下不逐位相同（nan / shuffle / noise 下相同）。原因：回归斜率用了矩阵乘向量（BLAS），同一窗口的结果会随矩阵总行数不同而在最后一位上不同。这不是用了未来信息，但不满足"逐位不变"，而且会让同一特征在不同长度的历史上算出不同的值。已改为逐元素相乘后逐行求和（`ops._reg`、`zh.chip_distribution`），代码里不再有 BLAS 调用；之后全部通过。

没有检测到的范围：检测是在抽到的 90 个股票 × 决策日上做的，不是对每一行；它检验的是代码对输入的依赖关系，**检验不了输入本身是否时点正确**（供应商的公告日是否偏早、回填是否改写过历史——那是 OA6、OA10 的事）。

## 5. PLAN 中定义不清、不可实现或与数据不符之处，及我的处理

1. **"核对原文之前不得写代码"（§5.1、§5.3、§5.3a）。** 已对照工作论文版，未对照期刊版（§2.3）。若组长认为必须对照期刊版，需要用户通过图书馆取得两篇 JFE 论文；公式各是一个函数，替换不影响其他代码。

3. **筹码分布：PLAN 要求先读参照实现再定初始筹码。** 读到的事实：(a) 参照实现**每个日期都从零筹码重新算最近 210 天**，没有初始筹码，最后除以总量——与 PLAN 占位规则（首日区间均匀铺满）不同；(b) 它输出的"平均成本"是 50% 分位（中位数），PLAN 写的是 mean cost；(c) 它的三角形叠加用的是格点上的密度高度，没有归一成"当日恰好加入 V 的质量"，一字板日加的质量与格数有关——我没有照搬这两处，改为每日精确加入质量 V；(d) 它的 90% / 70% 集中度是 (高 − 低)/(高 + 低)，PLAN 写的是区间宽度 / 价格，我按 PLAN；(e) PLAN 写"递推从首个特征日前 W 天开始"，可以读成一条贯穿全样本的递推，也可以读成逐日的 210 日滚动窗口；结合"价格轴取窗口的 [min low, max high]"我按滚动窗口实现。默认值按 PLAN 占位规则，参照实现的做法作为可选项；**最终取哪个请组长定**，两者的数值差别见 §3.5。

5. **"距上次事件天数：封顶 60，无事件为 0，指示变量可区分两种情况"。** 回看 20 日的指示变量区分不了"从未有过"与"40 天前有过"。我加了 `*_has_prior`。它以原始抓取的起点为界（左删失）：抓取起点之前的事件看不到。另外，天数从事件日算到决策日，最小值是 ℓ，所以 0 不会与真实事件混淆。
6. **同一股票同一天多条龙虎榜记录。** 当前磁盘上的龙虎榜表（252,219 行、215,665 个股票日）里，31,904 个股票日（14.8%）有多行，42,418 个股票日（19.7%）只有"多日累计"类原因的行。不同上榜原因各带一套席位金额，"连续三个交易日"类原因的金额是多日累计。PLAN 没有规定怎么合并。我的规则：优先用单日原因的行，其中取席位成交额最大的一行；只有多日原因时用它。机构表同样处理。这是我定的，会影响强度的口径。
7. **龙虎榜强度的分母"20 日平均成交额"没说截到哪天。** 我用截至 t−1 的 20 行（停牌日按 0 计）；均值为 0 或缺失且窗口内有事件时强度为 NaN。

### 7.6 与任务书或 PLAN 不符、我做了不同处理之处及理由

1. **FEA-7：三日累计偏离的阈值没有从规则日历读。** 规则日历 RC-18 的行只有单日判据（偏离 / 涨跌幅、振幅、换手），没有"连续三个交易日累计偏离"的阈值；`ro_trig_cum3_cnt_{1,5,20}` 这 3 列需要它（20% / 30%）。我不能改引擎，所以把这对数放在 `config.RO_CUM3_THRESHOLD`，并在清单里写明"不在规则日历、未对照规则原文"。按 F-20 的字面这是"第二份阈值"。需要组长定：加进规则日历，还是删这 3 列。
